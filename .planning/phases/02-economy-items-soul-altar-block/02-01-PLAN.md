## Phase Goal

**As a** necromancer player, **I want to** craft a Harvester, reap villagers into Soul
Fragments and Soul Blocks, and place a Soul Altar that accepts a socketed Soul Block, **so
that** the tangible soul economy exists and behaves correctly before any binding GUI is built.

> The ROADMAP `Goal:` line for Phase 2 is not written in user-story form. The story above is
> derived from `02-CONTEXT.md` Phase Boundary + the 4 ROADMAP success criteria. If it is
> wrong, run `/gsd mvp-phase 2` to fix the ROADMAP goal and re-plan.

<objective>
Wave 0 foundation for the whole phase: stand up every `DeferredRegister` this phase needs
(items, blocks, block-entity type, creative tab), create the content classes they bind to as
marker/skeleton classes (behaviour lands in the slice plans), delete the Phase 1
`DEBUG_MARKER`, wire everything into the `SecondShift` constructor in one visible block, and
extend the startup guardrail to cover all four registers plus a new `descriptionId` →
`en_us.json` resolution check. Finally, scaffold the ECON-02 GameTests so the one genuinely
custom mechanic (villager instakill) has a deterministic RED test before plan 02 makes it GREEN.

Purpose: this is the infrastructure that precedes the slices. Nothing here is user-facing
value; it is the registration backbone and the test/guardrail net that every later slice
hangs off. Getting the wiring + self-check right now makes the unbound-registry crash class
(the bug that killed the prior draft) structurally impossible for the new blocks, BE type,
and tab.

Output: a loadable mod with 4 bound registry objects (no textures/models/behaviour yet —
purple cubes and missing-model warnings are expected until the slices land), an extended
`ModRegistrySelfCheck`, a complete `en_us.json`, and a RED ECON-02 GameTest suite.
</objective>
