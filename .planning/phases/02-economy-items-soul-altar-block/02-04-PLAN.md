## Phase Goal

**As a** necromancer player, **I want to** craft a Harvester, reap villagers into Soul
Fragments and Soul Blocks, and place a Soul Altar that accepts a socketed Soul Block, **so
that** the tangible soul economy exists and behaves correctly before any binding GUI is built.

<slice>
**This slice:** the Soul Altar block exists and behaves — the last tangible piece before the
Phase 3 menu harness. After this plan a player can craft an altar (once they've crafted a
Soul Block), place it, right-click a Soul Block into it (one-way, eye-of-ender style),
save/reload and find it still socketed, and break it — with the empty vs charged break
behaviours of D-04. Zero GUI, zero binding, zero profession logic.

The charged render (embedded glowing Soul Block) is plan 02-05 — this plan verifies the
socket via `/data get block` and persistence, not visually.
</slice>

<key_decisions>
- **Socket path (D-03, PITFALLS §10):** `useItemOn(ItemStack, BlockState, Level, BlockPos,
  Player, InteractionHand, BlockHitResult)` returning **`ItemInteractionResult`** (1.21.1's
  odd-one-out signature — `@Override` mandatory so a wrong signature fails to compile).
  `useWithoutItem(...)` returns `InteractionResult.PASS` (no menu, no retrieval this phase).
- **One-way, no automation (D-03):** gate on `stack.is(SOUL_BLOCK_ITEM) && be.isEmpty()`; mutate
  the BE only inside `if (!level.isClientSide)`; NO `Capability` / `IItemHandler` exposed (already
  enforced in the BE from 02-01). No empty-hand retrieval path.
- **D-04 charged-altar break (implement as written, RESEARCH Open Question 1):** charged altar
  drops **nothing at all** — not the Soul Block, not the altar block itself — deals exactly
  `1.0F` damage to the breaking player only (a source that bypasses armor, e.g.
  `damageSources().magic()`), and spawns a `LightningBolt` with `setVisualOnly(true)` (flash +
  thunder, no fire, no collateral). Structure `getDrops` so the fallback ("altar block still
  drops, only the Soul Block is destroyed") is a **one-line change** — a single boolean branch on
  "was the BE charged".
- **Drop suppression mechanism (A5):** `getDrops(BlockState, LootParams.Builder)` reads the BE via
  `params.getOptionalParameter(LootContextParams.BLOCK_ENTITY)` (verify the constant name); if the
  BE was charged, return `List.of()`, else `super.getDrops(...)` (defers to the drops-self loot
  table). Do NOT stash a boolean on the block singleton (blocks are shared instances).
- **`playerWillDestroy` (A4):** `@Override` the 1.21.1 signature (verify return type against
  decompiled `Block.java`); do the lightning + `player.hurt` + `be.setHeldSoulBlock(EMPTY)` there
  (it has the `Player` ref and runs before BE removal), then `super`.
- **Altar recipe (D-06):** shaped, mid-cost, emerald as the soul-binding core — blackstone or
  deepslate frame + `minecraft:soul_soil` + a skull or `minecraft:bone` + 1-2 `minecraft:emerald`.
- **Altar advancement (D-15 step 3):** `minecraft:recipe_crafted` on `secondshift:soul_block`
  (or `inventory_changed` on `secondshift:soul_block`) -> `rewards.recipes
  [secondshift:soul_altar]`; description clue "set a job-site block on top".
</key_decisions>
