## Phase Goal

**As a** necromancer player, **I want to** craft a Harvester, reap villagers into Soul
Fragments and Soul Blocks, and place a Soul Altar that accepts a socketed Soul Block, **so
that** the tangible soul economy exists and behaves correctly before any binding GUI is built.

<slice>
**This slice:** the visual payoff of the socket. After this plan, socketing a Soul Block
makes it appear embedded and glowing in the altar top (eye-of-ender style, D-05), and the
mandatory `./gradlew runServer` client-class-leak gate for the phase is closed. This is the
last plan of Phase 2.

Not in this slice: any custom `SoundEvent`/`ParticleType` registration (Phase 10, POL-05);
the altar's ambient wisp beyond the charged render.
</slice>

<key_decisions>
- **Charged render (D-05 / Discretion):** a client-only `BlockEntityRenderer<SoulAltarBlockEntity>`
  registered from `EntityRenderersEvent.RegisterRenderers` (mod bus, `Dist.CLIENT`) — NOT an
  emissive baked model + particle ticker. A static model cannot cleanly do "recessed Soul Block
  appears only when charged" without extra blockstate properties, and vanilla block models have
  no emissive flag. The BER also owns the wisp. Per `02-RESEARCH.md` Alternatives + Anti-Patterns.
- **Emissive:** render the embedded Soul Block model at `LightTexture.FULL_BRIGHT` (packed light
  override) — eye-of-ender style, no bob (D-05).
- **Registration site:** extend the existing `client/ClientModBusEvents.java` (already a
  `@EventBusSubscriber(bus = Bus.MOD, value = Dist.CLIENT)` class) — do NOT create a new
  subscriber class. This is the ONLY place `SoulAltarRenderer` may be named (PITFALLS §9).
</key_decisions>
