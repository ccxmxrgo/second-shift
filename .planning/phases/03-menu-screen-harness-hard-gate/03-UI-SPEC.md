# Phase 3 — UI Design Contract

> Visual and interaction contract for the **Binding Altar** in-game GUI.
> Domain: Minecraft 1.21.1 / NeoForge 21.1.248 `AbstractContainerScreen<BindingAltarMenu>` —
> NOT a web/app UI. No CSS, no Tailwind, no component library. All coordinates are texture
> pixels; all colors are ARGB ints. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase is a **HARD GATE**. The screen is deliberately near-empty: vanilla container chrome
+ the player inventory + exactly ONE display-only mod slot + the title. Nothing else. Its job is
to lock the pixel values so the planner and executor do not improvise a bigger screen.

## Screen Geometry (the spacing scale for this domain)

Minecraft container GUIs are measured in texture pixels on an 18px slot grid, not a 4px web
scale. Declared values for this screen:

| Token | Value | Usage |
|-------|-------|-------|
| `imageWidth` | 176 px | Background panel width (vanilla default — do not change) |
| `imageHeight` | 166 px | Background panel height (vanilla default — do not change) |
| Slot pitch | 18 px | Center-to-center spacing of any slot grid (16px item + 1px border ×2) |
| Edge margin | 8 px | Left/right inset of inventory grid and labels from panel edge |
| Title inset | `titleLabelX = 8`, `titleLabelY = 6` | Vanilla default position for the title string |
| Inventory label | `inventoryLabelX = 8`, `inventoryLabelY = 72` (`imageHeight − 94`) | Vanilla default — leave as inherited |

**Blit:** one call — `guiGraphics.blit(TEXTURE, leftPos, topPos, 0, 0, imageWidth, imageHeight)`
where `leftPos = (width - imageWidth) / 2`, `topPos = (height - imageHeight) / 2`. No nine-slice
scaling, no tiling — a single fixed 176×166 region.

**Texture file:**
- Path: `src/main/resources/assets/secondshift/textures/gui/binding_altar.png`
- Canvas: 256×256 PNG (power of two). GUI content occupies the top-left 176×166 rectangle; the
  rest is transparent/unused.
- `ResourceLocation`: `secondshift:textures/gui/binding_altar.png`
- Placeholder art is acceptable this phase (POL-03 precedent from Phase 2). It must still be a
  real, readable panel — a bordered dark stone/soul-soil panel with the recessed slot cavities
  drawn in — not a flat magenta box and not a missing-texture checkerboard.

### Slot coordinates (menu-space, i.e. relative to `leftPos`/`topPos`)

| Slot | `Slot#x` | `Slot#y` | Notes |
|------|----------|----------|-------|
| Mod slot — socketed Soul Block (display-only) | 80 | 35 | Horizontally centered (panel center x = 88; 16px item spans 80–96). Vertically centered in the open area between the title and the inventory label. |
| Player inventory row 1 (indices 9–17) | 8, 26, 44, … (+18) | 84 | Vanilla layout |
| Player inventory row 2 (indices 18–26) | 8, 26, 44, … (+18) | 102 | Vanilla layout |
| Player inventory row 3 (indices 27–35) | 8, 26, 44, … (+18) | 120 | Vanilla layout |
| Player hotbar (indices 0–8) | 8, 26, 44, … (+18) | 142 | Vanilla layout |

The background texture must draw an 18×18 recessed slot frame at panel-pixel `(79, 34)` (one
pixel outside the mod slot's item origin) plus the standard 3×9 + hotbar recesses for the player
inventory.

### Mod slot behavior contract (D-06)

- **Display-only.** The player cannot take from or place into it this phase.
- Implement as a `Slot` subclass in `menu/` (common) overriding `mayPickup(Player) → false` and
  `mayPlace(ItemStack) → false`. (D-06 permits either the subclass or flag overrides — subclass
  is the contract choice: it is self-documenting and reused in Phase 5.)
- The slot's backing container is the `SoulAltarBlockEntity`'s existing single `heldSoulBlock`
  stack (read path only this phase).
- No hover tooltip beyond vanilla's automatic item-name tooltip. No custom highlight, no
  animation, no pulsing.

## Typography

Minecraft pixel font only. One glyph size (≈7px cap height, 9px line advance). "Weight" in this
domain is the presence/absence of the 1px drop shadow.

| Role | Renderer | Color (ARGB) | Shadow | Position |
|------|----------|--------------|--------|----------|
| Screen title — "Binding Altar" | `Font#drawInBatch` via `renderLabels` → `guiGraphics.drawString(font, title, titleLabelX, titleLabelY, ...)` | `0xFF404040` (vanilla container-label grey) | no shadow | (8, 6) menu-space |
| "Inventory" label | inherited `renderLabels` default | `0xFF404040` | no shadow | (8, 72) menu-space |
| POL-08 action-bar messages | `player.displayClientMessage(component, true)` — rendered by the HUD, not this screen | vanilla action-bar white | vanilla | HUD action bar |

No other text is drawn on this screen this phase. No body copy, no helper text, no button
labels (there are no buttons).

## Color

All values ARGB ints (`0xAARRGGBB`). This is a fixed single-theme GUI — no light/dark variants,
no hover states.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (~60%) | texture art: dark soul-soil / obsidian panel, roughly `0xFF2A2620`–`0xFF3A3430` range | The background panel body |
| Secondary (~30%) | texture art: raised bevel / frame + recessed slot cavities, roughly `0xFF5A5048` edge highlight over `0xFF1C1A16` cavity shadow | Panel border, slot recesses, inventory grid |
| Accent (~10%) | soul-cyan, approx `0xFF4EE8E8` | Reserved EXCLUSIVELY for a faint glow ring drawn into the texture around the single mod slot, signalling "this is where the soul goes". Nothing else. No accent on the player inventory, no accent text. |
| Label text | `0xFF404040` | Title + "Inventory" label (vanilla convention) |
| Semantic / destructive | none | No destructive action exists on this screen this phase (the socket is non-consuming; binding is Phase 5) |

Accent reserved for: the mod-slot glow ring in the background texture — and only that.

## Copywriting Contract

**Tone:** HR-necromancer — corporate-onboarding language applied to raising the dead, consistent
with the Phase 2 advancement clue chain ("open a position", "payroll", "what the village owes
you"). Applies to messages only. **The title is plain: exactly "Binding Altar"** (fixed by
Success Criterion 1 — no flavor).

| Element | `en_us.json` key | Copy |
|---------|------------------|------|
| Screen title | `container.secondshift.binding_altar` | `Binding Altar` |
| Primary CTA | — | None this phase. No confirm/cancel/bind button exists until Phase 5. |
| Empty state (mod slot with no Soul Block) | — | No on-screen empty-state text. The slot simply renders empty; the screen only opens once a Soul Block is socketed (D-01), so a truly empty mod slot is not a normal reachable state while the screen is open. |
| Error — no job-site block on top of altar | `message.secondshift.altar.no_job_block` | `The position is unfilled. Set a job-site block atop the altar before you file the paperwork.` |
| Error — block on top is not a workstation (POI absent or unmapped) | `message.secondshift.altar.not_a_workstation` | `That block posts no job. Only a real workstation defines the role.` |
| Error — right-clicked empty altar with no Soul Block in hand | `message.secondshift.altar.no_soul_block` | `Nothing to bind. Bring a Soul Block to staff this altar.` |
| Forced close — altar was broken | `message.secondshift.altar.closed.altar_gone` | `The altar is gone. Consider the interview concluded.` |
| Forced close — job-site block removed | `message.secondshift.altar.closed.job_gone` | `The workstation was removed. The position is rescinded.` |
| Forced close — player walked out of range | `message.secondshift.altar.closed.too_far` | `You stepped away from the altar. The paperwork goes unfiled.` |
| Destructive confirmation | — | None. No destructive action on this screen this phase. |

**Message delivery convention (POL-08, locked for this phase and forward):**
- All player-facing status messages are `Component.translatable(key)` sent via
  `player.displayClientMessage(component, true)` — the **action bar** (the `true` flag), never
  drawn on the screen surface, never chat.
- Sent server-side from `SoulAltarBlock` (pre-open validation) and from the menu's
  `stillValid` / close path (forced-close reasons, D-12). On forced close, send the message
  first, then close the container.
- Deferred POL-08 cases (empty trade pool, altar with no valid quarters) are explicitly NOT in
  this phase (D-13) — do not add keys for them now.

## Interaction Contract

| Trigger | Result | Side |
|---------|--------|------|
| Right-click altar holding a Soul Block; altar empty + job block above maps to a profession | Socket the Soul Block into the BE **and** open this screen in the same click (D-01) | server opens via `serverPlayer.openMenu(provider, buf -> buf.writeBlockPos(pos))` |
| Right-click altar empty-handed; altar already charged + job block above maps to a profession | Re-open this screen (D-02) | server |
| Right-click altar holding a Soul Block; altar already charged | Just open the screen — no second socket, no error (D-04) | server |
| Any invalid precondition | No screen; matching action-bar message (see copy table); no crash (Success Criteria 1 & 3) | server |
| Altar broken / job block removed / player > ~8 blocks away while screen open | `stillValid` fails → screen closes + forced-close action-bar message (D-12) | server-authoritative (`AbstractContainerMenu.stillValid(ContainerLevelAccess.create(level, pos), player, ModBlocks.SOUL_ALTAR.get())` + vanilla distance check) |
| Hand-crafted / out-of-range menu packet | Rejected server-side by `stillValid`, no crash (Success Criterion 4) | server |
| Player clicks/drags the mod slot | Nothing — `mayPickup` / `mayPlace` both false (D-06) | client + server |

No animations, no transitions, no sound designed in this phase (bind/harvest SFX are Phase 5 /
POL-05). No responsive behavior — one fixed 176×166 layout at all GUI scales (vanilla handles
GUI-scale integer scaling).

## Out of Scope for This Screen (Phase 5+)

Do not add, sketch, or reserve pixel space for: employee name field, profession/HR header,
tier display, trade picker list, career-path preview, confirm/cancel buttons, happiness
indicator, `ContainerData` sync, any `CustomPacketPayload`. The screen has exactly one mod slot
and a title this phase.
