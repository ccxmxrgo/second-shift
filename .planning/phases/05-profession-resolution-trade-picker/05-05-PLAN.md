<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Client → `SelectTradesPayload` → server | Untrusted indices array and name string; server must independently re-derive every fact about what was actually offered and what is actually legal to select |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-05-07 | Tampering | `validateIndices` — out-of-range index | mitigate | Bounds-check every index against `candidates.size()`, reject the whole payload (return `null`, no partial apply) on any violation |
| T-05-08 | Tampering | `validateIndices` — duplicate index (pick one offer twice) | mitigate | `LinkedHashSet`-based dedup detection rejects the whole payload on any repeat |
| T-05-09 | Tampering | `validateIndices` — client ignores the 2-selection cap or fakes auto-lock | mitigate | Server enforces the `<=2` count invariant and re-derives the full candidate set whenever `candidateCount <= 2`, ignoring the client's claimed selection entirely in that case |
| T-05-10 | Tampering | `sanitizeName` — formatting-code / control-character injection into a persisted, repeatedly-rendered name | mitigate | Strip `§` and `\p{Cc}` control characters, trim, cap at 32 chars, fall back to the pre-filled default if the sanitized result is blank |
| T-05-11 | Elevation of Privilege / Race | Double/duplicate rapid Confirm sends against one altar | mitigate | `be.isEmployeeBound()` checked as the FIRST statement inside the atomic `access().execute` lambda, set `true` only after `EmployeeManager.bind` returns successfully and before `sp.closeContainer()` — a second send inside the same or a later tick sees the flag already set and no-ops |
| T-05-12 | Denial of Service | Oversized/malformed serverbound payload | accept | NeoForge's built-in 32 KiB serverbound payload cap already bounds worst-case size; `validateIndices` rejects any structurally invalid content immediately with O(n) cost |
| T-05-13 | Repudiation / Data Loss | `EmployeeManager.bind` throws after sockets are already consumed | accept | No existing repair mechanic in this codebase; failure is caught, logged clearly at ERROR level with the altar position, and `employeeBound` is left `false` (never set before a successful bind) so the failure is at least loud and does not permanently soft-lock the altar's occupancy flag |
</threat_model>
