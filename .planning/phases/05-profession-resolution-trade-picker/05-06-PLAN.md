    net.minecraft.client.gui.components.ObjectSelectionList<TradeCandidateList.Entry>`. Constructor
    takes `(Minecraft minecraft, int width, int height, int top, int itemHeight, List<MerchantOffer>
    candidates, boolean autoLocked, java.util.function.IntConsumer onSelectionChanged)` and
    populates one `Entry` per candidate via `addEntry(new Entry(index, offer, autoLocked))`.
    `Entry` (implements `ObjectSelectionList.Entry<Entry>` — mirror the nested-static-class pattern
    vanilla's own `ObjectSelectionList` subclasses use) holds the candidate index, the
    `MerchantOffer`, a `selected` boolean (initialized `true` if `autoLocked`, else `false`), and
    renders per UI-SPEC's row anatomy exactly: `[2px pad][18px item icon via
    GuiGraphics#renderItem(offer.getResult(), x, y)][4px gap][item display name via offer.getResult().getHoverName()][flex][price text: offer.getCostA().count() + " " + offer.getCostA().getHoverName() (+ " + " + costB if offer.getCostB().isPresent())][2px pad]`.
    Implement all 4 row states from UI-SPEC's table: unselected/not-hovered = fill `0xFF8B8B8B`, no
    border; hovered = same fill + `0x80FFFFFF` overlay; selected (not locked) = `0xFFFFD700` 1px
    border + `0x40FFD700` fill overlay + a checkmark glyph (draw `"✓"` or a simple filled
    triangle via `GuiGraphics#fill` if no checkmark glyph renders cleanly in the vanilla font) left
    of the icon, gold-tinted; locked (auto-selected, `autoLocked == true`) = same visual as selected
    PLUS the muted-gray `"(locked)"` label (new key
    `gui.secondshift.binding_altar.trade_locked`) appended after the price, and the row's
    `mouseClicked` override returns `false` immediately (non-interactive, no-op click, matching
    D-04's "no-op don't disable-gray-out" tone). For a non-locked row, `mouseClicked` toggles
    `selected`: if turning ON and the list's already-selected count (query the parent list, e.g. via
    a package-private `int selectedCount()` method querying all `Entry` children) is already 2,
    do NOT toggle — instead set a short-lived `rejectFlashTicksRemaining = 6` field on the entry and
    return `true` (consumed, no state change) so `render` can draw the destructive-red `0xFFFF5555`
    border for those remaining ticks (decrement once per `render` call using the render's own tick
    counter or a simple counter field, since `ObjectSelectionList.Entry` has no built-in tick hook —
    decrement inside `render` itself, guarded so it only decrements once per game tick using
    `partialTick`/a stored last-seen tick, or simply decrement once per `render` call if simplicity
    is acceptable here per CONTEXT.md's "low-friction micro-interaction" framing). On every
    successful toggle, invoke the `onSelectionChanged` callback with the row's index (or `-1` — the
    exact callback contract is this class's own choice, document it in a one-line Javadoc on the
    constructor) so the owning `BindingAltarScreen` can recompute the live selected-index list for
    Confirm.
