# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** This is not a web/React UI. The "screen" is a vanilla Minecraft
`AbstractContainerScreen<BindingAltarMenu>` rendered with LWJGL immediate-mode calls
(`GuiGraphics#blit`/`drawString`/widgets), extending the already-shipped
`BindingAltarScreen`/`BindingAltarMenu` (Phase 3/4) rather than replacing them. The shadcn
gate in the standard UI-researcher process does not apply — no `components.json`, no
React/Next/Vite stack detected (confirmed: pure Gradle/NeoForge Java project). All "design
tokens" below are translated into Minecraft's own vanilla GUI idiom (pixel-grid widgets,
the vanilla default font, `ObjectSelectionList`-style row conventions) per this phase's
explicit brief, not a generic web design system.

## Spacing Scale

Minecraft's GUI grid is not a web 8-point grid — it is driven by the vanilla 18px inventory
slot and the existing menu's own pixel placements. Declared values (all multiples of the
existing menu's 2px base unit, not 4px — **documented exception**, this is a vanilla-GUI
project, not a web one):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 2px | Icon-to-text gap inside a candidate row |
| sm | 4px | Inline padding (row internal padding, text baseline offsets) |
| md | 8px | Panel margin — matches existing menu's `leftPos + 8` soul-slot/button inset |
| lg | 18px | Slot cell / one vanilla inventory slot (used for item-icon column width in candidate rows) |
| xl | 20px | List row height (18px icon + 1px top/bottom breathing room) and button height (vanilla `Button` default) |
| 2xl | 36px | Section gap: name field block to candidate list, and candidate list to Confirm button |

Exceptions: Base unit is 2px (vanilla widget/atlas alignment), not the template's default
4px web grid — intentional, matches this phase's Minecraft-native brief. All values above
are still even multiples of 2px for pixel-grid/texture-alignment cleanliness.

## Typography

Minecraft's built-in font has one family, fixed glyph metrics (~8px cap height, ~9px line
height at scale 1.0), and exactly two weight states (regular / bold via `Style#withBold`).
"Sizes" below are achieved via `PoseStack` scale factors on top of the base font, which is
the standard vanilla technique (used for anvil rename-cost text, sign editors, etc.).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (row item name, row price/count text) | scale 1.0 (~9px line) | regular | 1.0 (single vanilla text line, no wrap inside a row) |
| Label (secondary row text: "(locked)" tag, item count, name-field label) | scale 1.0 (~9px line) | regular, color `0xFFA0A0A0` (vanilla muted gray, matches tooltip lore text) | 1.0 |
| Heading (screen title "Binding Altar", "Name:" field label) | scale 1.0 (~9px line) | regular, color `0xFF404040` (vanilla `AbstractContainerScreen` default title color) | 1.0 |
| Display (profession name callout, e.g. "Librarian") | scale 1.5 via `PoseStack#scale` (~13-14px effective) | **bold**, color accent gold `0xFFFFD700` | 1.0 |

Only 2 weights used total (regular, bold) — bold reserved for the Display role only, per
the accent-reservation rule below.

## Color

Minecraft GUI panels are texture-blitted, not flat CSS fills, so "dominant/secondary" map
to the existing panel texture plus the programmatic fills needed for the new scrollable
candidate list (which extends past the original static texture area).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Existing `binding_altar.png` panel texture (vanilla light-gray inventory panel, ~`#C6C6C6` family) | Screen background — reuse and extend the existing texture, do not introduce a new flat color for the base panel |
| Secondary (30%) | `0xFF8B8B8B` (vanilla slot-bevel gray) for candidate-row backgrounds; `0x80000000` for the row-list's own inset panel if drawn outside the static texture | Candidate row backgrounds, list inset panel, name-field `EditBox` background (vanilla `EditBox` default is already this tone — reuse, do not restyle) |
| Accent (10%) | `0xFFFFD700` (vanilla gold, matches enchant/price emphasis conventions) | **Reserved exclusively for:** (1) selected-candidate-row border, (2) the "Display" profession-name text role above, (3) the auto-locked-row badge icon tint. Never used for body text, buttons, or any other element. |
| Destructive/error | `0xFFFF5555` (vanilla error red, matches "cannot afford"/invalid-state conventions) | **Reserved exclusively for:** inline GUI error/empty-state text (empty tier pool message rendered inside the screen). Chat/action-bar themed messages (altar-occupied, invalid job item) stay default white per the existing `en_us.json` convention — do not recolor those. |

Row hover overlay (not a 60/30/10 color, a vanilla interaction convention): `0x80FFFFFF`
semi-transparent white, matching `ObjectSelectionList`'s built-in hover tint. Row selected
fill: `0x40FFD700` (accent gold at 25% alpha) layered under the gold border above.

Accent reserved for: selected-row border + selected-row checkmark glyph, the profession-name
Display text, and the auto-locked badge icon only — never buttons, never unselected rows,
never body/label text.

## Screen Layout (Minecraft Container Screen Contract)

This section supplements the template's web-oriented sections with the concrete
container-screen contract the executor needs; it is required reading alongside Spacing/Color/Typography above.

**Canvas:** `binding_altar.png` must grow from the existing 176×166 to **200×222** (`imageWidth=200, imageHeight=222` in `BindingAltarScreen`). Width grows to fit item-icon + name + price per row without truncation; height grows to fit the name field, an ~5-row-visible candidate list, and the Confirm button above the untouched player-inventory grid (which stays at its existing `84`/`142` y-offsets — do not move it, only insert content above it by extending panel height upward of that fixed grid).

**Vertical composition (top to bottom, `topPos + y`):**
| Region | Y range | Contents |
|--------|---------|----------|
| Title | 6–15 | Vanilla-default `AbstractContainerScreen` title render ("Binding Altar") — unchanged |
| Name field | 20–36 | `Label` "Name:" (md=8px left inset) + `EditBox` pre-filled with `EmployeeNames` default, 32-char cap (per RESEARCH.md Finding 3 A1), sanitizes `§`/control chars, blank-on-confirm falls back to default (D-03) |
| Candidate list | 40–130 | Scrollable row list (vanilla `AbstractSelectionList` pattern), row height 20px (xl token), ~5 rows visible before scroll, scrollbar only if `candidates.size() > 5` (Claude's-discretion item from CONTEXT.md, resolved here) |
| Confirm button | 134–154 | `Button.builder("Confirm Hire", ...)` reusing the existing translatable key `gui.secondshift.binding_altar.confirm` — same label, now wired to `SelectTradesPayload` instead of Phase 4's throwaway `BindEmployeePayload` |
| Player inventory | 84(orig)/142(orig) shifted down by the same insertion offset | Unchanged 3×9 grid + hotbar — **do not re-lay this out**, only shift its container-relative y by the amount the panel grew above it |

**Candidate row anatomy (one row = one materialized `MerchantOffer`):**
`[2px pad][18px item icon: offer.getResult()][4px gap][body text: item name][flex][body text: price — offer.getCostA() (+ getCostB() if present)][2px pad]`
Row is a single click-target (D-02: click-to-toggle, not a separate checkbox widget).

**Row visual states (all four must be implemented, each visually distinct):**
| State | Visual |
|-------|--------|
| Unselected, not hovered | Secondary fill `0xFF8B8B8B`, no border |
| Hovered (unselected) | Secondary fill + `0x80FFFFFF` hover overlay |
| Selected (≤2 chosen) | Accent gold border `0xFFFFD700` (1px) + `0x40FFD700` fill overlay + small checkmark glyph left of the item icon, accent-tinted |
| Locked/auto-selected (pool ≤ 2, PICK-04) | Same visual as Selected, plus the muted-gray "(locked)" label token appended after the price, row is non-interactive (clicks no-op — it is already permanently selected, matching D-04's "no-op, don't disable-gray-out" tone) |

**Cap-reached interaction (resolves an open gap not fully specified upstream):** clicking a
3rd row while 2 are already selected (and the pool is not auto-locked) does **not** replace
the oldest selection. The row instead briefly flashes the destructive-red `0xFFFF5555`
border for ~6 ticks (a "rejected" flash, not a themed chat message — this is a fast,
low-friction micro-interaction, not an error state worth interrupting the player for).

**G-2 socket render coordination (per RESEARCH.md Finding 2 — visual, not menu-screen, but same phase contract):** the hovering job-item render (`HOVER_Y = 1.35D`, `HOVER_SCALE = 0.4F`, `SPIN_DEG_PER_TICK = 1.0F`, ambient `packedLight`) must use its **own** `pose.pushPose()/popPose()` pair, separate from the existing embedded Soul Block render (`EMBED_Y = 0.78D`, `EMBED_SCALE = 0.5F`, static, `LightTexture.FULL_BRIGHT`) — the two must never share a transform stack, and the two Y-offsets must keep a visible gap (0.78 vs 1.35 — already ≥0.5 block apart, confirmed sufficient to prevent overlap at their respective scales).
